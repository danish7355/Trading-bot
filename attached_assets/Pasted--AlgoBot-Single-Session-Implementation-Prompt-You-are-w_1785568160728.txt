## 1. Fix the "Trade Guard Active — Stale Data" banner (root cause, not a patch)
This banner means the frontend isn't getting real-time price ticks. Diagnose and fix:
- Confirm whether the Binance WS (`connectPriceStream`) is actually delivering `message`
  events after connecting — log a timestamp on every tick received, not just on connect.
- The frontend's "live/stale" status must be derived from **time since last actual price
  tick**, not from "socket handshake succeeded." A socket can be open with zero data
  flowing — that's the current bug.
- Add a backend watchdog: if no tick has been received for >15s while the WS reports
  "open," log a clear warning and trigger a WS reconnect (don't wait for the socket to
  close on its own).
- Verify the candle-fetching module (logs `[CANDLES] All fallbacks failed`) isn't causing
  request storms that get the IP flagged and silently throttled by Binance — this can
  suppress WS data even when the socket looks connected. Rate-limit and stagger candle
  fetches across symbols (small delay between requests, not all 120 at once).

## 2. Live price "pulse" animation
- On every price tick, briefly flash the price cell: green flash + up-tick if price
  increased, red flash + down-tick if decreased, fading back to normal over ~400–600ms.
- Pure CSS transition + a toggled class on tick (no animation library needed) — this
  keeps it cheap on both bundle size and render cost.
- Apply to every price cell in the signals table and dashboard price displays, not just
  one place.

## 3. Separate signals by market — never mixed
- Signals tab must show **one market at a time**, in clearly separate sub-tabs or filters
  (e.g. Crypto / Forex / Stocks / whatever markets you actually have data sources for —
  do not fabricate signals for markets you have no real data feed for).
- If only crypto (Binance) data currently exists, say so plainly in the UI (e.g. disable
  or label other market tabs as "Coming soon") rather than mixing placeholder data into
  the crypto signal list.
- Backend: tag every signal object with its `market` field at the source, and never merge
  arrays from different markets before sending to the frontend.
